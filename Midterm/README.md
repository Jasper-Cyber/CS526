## Introduction

The midterm has three problems. Every program is written in Python 3 and reads its input from a file named on the command line, or from standard input.

| Problem | Program | What it does |
|---|---|---|
| 1. Snowfall | `snowfall.py` | Reads cumulative snowfall totals and decides whether any three consecutive days hold strictly more than half of all the snow. Prints `<input> solution: <YES\|NO>`. |
| 2. Pandemic | `pandemic.py` | Spreads an infection over an N×N grid day by day until it stops, prints the board for each day, and reports whether any healthy counties are left. |
| 3. Symbol Puzzle Game | `puzzle_game.py` | Checks whether an n×n symbol board is valid: no symbol repeated in a row, column or √n×√n sub-board, and no unlisted symbols. |

`run_tests.py` runs every program on all of its input files, writes the output files, and compares each result with the answer files.

`readme.txt` is the plain-text readme the assignment asks for. It has the same algorithm descriptions, code explanations and commands as this file.

## How to run

### Requirements

- **Python 3.8 or newer.** `puzzle_game.py` uses `math.isqrt`, which was added in Python 3.8. Check your version with `python --version`.
- **Nothing to install.** Only the Python standard library is used.

### Step 1: Open a terminal in the `Midterm` folder

```
cd path/to/CS526/Midterm
```

Run every command below from this folder.

### Step 2: Run a program with the input file name

```
python snowfall.py snowfall_input1.txt
```

This form works the same in **every** terminal: Windows PowerShell, Windows Command Prompt, Git Bash, macOS and Linux. On macOS and Linux, type `python3` if `python` is not found.

The programs also read standard input when no file name is given:

| Shell | Standard input form |
|---|---|
| Windows Command Prompt, Git Bash, macOS / Linux | `python snowfall.py < snowfall_input1.txt` |
| Windows PowerShell | `Get-Content snowfall_input1.txt \| python snowfall.py` |

PowerShell does not support `<`. It stops with `The '<' operator is reserved for future use`, which is why it needs the `Get-Content` form.

## Problem 1: Snowfall

### Algorithm

The array already holds running totals, so the snowfall of any three consecutive days takes a single subtraction:

```
snowfall on days i, i+1, i+2  =  A[i+2] - A[i-1]        (with A[0] = 0)
```

The program slides this three-day window from days 1–3 up to days (n−2)–n and compares each window with the total snowfall A[n]. It answers **YES** as soon as one window satisfies

```
2 * window > A[n]
```

This means "the window is strictly more than half of A[n]", without dividing by 2. If no window passes, or if n < 3 (so there is no window at all), the answer is **NO**.

For `snowfall_input1.txt`, A = 1 4 10 14 15 17 17 23, total 23, half 11.5:

```
days 1-3:  A[3] - A[0] = 10 - 0 = 10      2 * 10 = 20 > 23?  no
days 2-4:  A[4] - A[1] = 14 - 1 = 13      2 * 13 = 26 > 23?  yes  ->  YES
```

**Complexity:** O(n) time, one pass. O(n) memory.

### Code

- **`has_heavy_window(totals)`.** `A = [0] + totals` puts a 0 in front, so the list indexes match the problem exactly: `A[0] = 0`, `A[1]` = day 1, and so on. `for i in range(1, n - 1)` visits the windows that start on days 1 to n−2 and returns `True` at the first window where `2 * (A[i + 2] - A[i - 1]) > A[n]`.
- **`solve(text)`.** Reads n and the n values, converts the values with `Fraction`, and returns `<input> solution: <YES|NO>`, where `<input>` is the values exactly as written in the file.
- **`main()`.** Runs `solve()` on every file name on the command line, so all inputs can be tested in one run. With no file name it reads standard input.

### Results

| Input | Total | Half | Deciding window | Answer |
|---|---|---|---|---|
| 1 | 23 | 11.5 | days 2–4 = 13, more than half | YES |
| 2 | 886 | 443 | largest is days 14–16 = 197, below half | NO |
| 3 | 32 | 16 | largest is days 2–4 = 16, **exactly** half | NO |
| 4 | 5 | 2.5 | days 1–3 = 3, more than half | YES |
| 5 | 3 | 1.5 | days 1–3 = 3, the only window | YES |

- **Input 3** tests the "strictly more than half" rule: days 2–4 give 19 − 3 = 16, exactly half of 32, so the answer is NO.
- **Input 5** is not in the assignment's list. With n = 3 there is exactly one window, days 1–3, and it holds all of the snow.

## Problem 2: Pandemic

### Algorithm

The state is an N×N grid of `True` (infected) and `False` (healthy). Each day:

1. find every healthy county with **at least two** infected neighbors (up, down, left, right; diagonals do not count), and
2. only after the whole list for that day is found, mark them all infected.

Doing step 2 after step 1 is what makes all counties update at the same time. A county infected today cannot help infect another county until tomorrow. The simulation stops on the first day with no new infections. If any county is still `False`, there are healthy counties left.

**Only the neighbors of new infections are checked.** A healthy county's number of infected neighbors only goes up when one of its neighbors becomes infected. So each day the program checks only the healthy neighbors of the counties infected the day before, instead of scanning the whole grid.

**Complexity:** every county is infected at most once, and each new infection leads to at most 4 neighbor checks of 4 cells each, so the whole simulation takes **O(N²)** time. A full-grid scan would cost O(N²) *per day* instead. For example, a 1000×1000 grid with only the diagonal infected keeps spreading for 999 days until every county is infected. This program finishes it in about 5 seconds, while a full scan would check 1,000,000 counties on each of those days.

### Code

- **`neighbors(r, c, n)`.** Yields the counties above, below, left and right of `(r, c)`, skipping any outside the grid.
- **`new_infections(grid, recent)`.** `candidates` is the **set** of healthy neighbors of the counties in `recent`, so a county next to two recent infections is checked once. `sum(...)` counts each candidate's infected neighbors (`True` counts as 1, `False` as 0), and the candidates with 2 or more are returned. The grid is not changed here.
- **`simulate(n, initial, show)`.** Builds the grid, marks the initial counties and prints Day 1. Then it repeats: find `new`, stop if it is empty, otherwise mark it, print the next day, and use `new` as `recent` for the following day.
- **`main()`.** Reads the input, runs the simulation and prints the final message as the last line. `--quiet` hides the daily boards.

## Problem 3: Symbol Puzzle Game

### Algorithm

The board is read once, cell by cell. Three lists of sets remember which symbols have been seen so far:

| Set | Holds |
|---|---|
| `rows[r]` | symbols already seen in row r |
| `cols[c]` | symbols already seen in column c |
| `boxes[b]` | symbols already seen in sub-board b |

For each non-empty cell `(r, c)` holding symbol `v`:

- `v` is not one of the n listed symbols → **invalid**
- `v` is already in `rows[r]`, `cols[c]` or `boxes[b]` → **invalid** (repeated)
- otherwise add `v` to all three sets and go on

If every cell passes, the board is valid. Empty cells (`.`) are skipped, so they never make the board invalid.

**Which sub-board a cell is in.** With k = √n (2 for 4×4, 3 for 9×9):

```
b = (r // k) * k + (c // k)
```

`r // k` is the sub-board's row and `c // k` its column. For a 9×9 board:

| | cols 0–2 | cols 3–5 | cols 6–8 |
|---|---|---|---|
| **rows 0–2** | 0 | 1 | 2 |
| **rows 3–5** | 3 | 4 | 5 |
| **rows 6–8** | 6 | 7 | 8 |

For example, cell (4, 7) is in sub-board (4 // 3) × 3 + (7 // 3) = 3 + 2 = **5**.

**Complexity:** O(n²) time, because each of the n×n cells is visited once and every set lookup or insert takes O(1). O(n²) memory for the sets. The program stops at the first broken rule.

### Code

- **`read_input(text)`.** Line 1 gives n. Line 2 is split at the commas to get the symbols. The next n lines are split at the commas to get the board as a list of rows. Spaces around values are removed and blank lines are skipped.
- **`is_valid(n, symbols, board)`.** `k = isqrt(n)` is the sub-board size and `allowed = set(symbols)` makes the "is this a listed symbol" check O(1). The two nested loops apply the checks above, returning `False` at the first problem and `True` at the end.
- **`main()`.** Reads the input and prints `The board is valid` or `The board is invalid`.

### Results

| Input | Size | Output | Reason |
|---|---|---|---|
| 1 | 9×9 | The board is valid | no rule is broken |
| 2 | 9×9 | The board is invalid | `}` repeated, see below |
| 3 | 4×4 | The board is valid | the example board from the assignment |
| 4 | 4×4 | The board is invalid | `@` repeated, see below |

- **`puzzle_game_input2.txt`** is input 1 with one change: row 0, column 0 holds `}` instead of `%`. That `}` is now repeated in **column 0** (rows 0 and 3) and in the **top-left 3×3 sub-board** (cells (0,0) and (2,2)).
- **`puzzle_game_input4.txt`** is input 3 with one change: row 1, column 1 holds `@` instead of `*`. That `@` is now repeated in the **top-left 2×2 sub-board** (cells (0,0) and (1,1)). Its row and column are fine, so only the sub-board check catches it.

## Interesting aspects

- **Prefix sums turn every window into one subtraction (Problem 1).** Because the input is already cumulative, no daily amounts have to be rebuilt and no window has to be added up. Each check is `A[i+2] - A[i-1]`, so the whole answer is one O(n) pass.
- **Comparing `2 * window > total` instead of `window > total / 2` (Problem 1).** Doubling the window instead of halving the total keeps the comparison in exact arithmetic. This matters most at exactly half, as in input 3, where any rounding error would flip the answer. Values are read as `Fraction`, so decimal snowfall such as `2.5` is exact too.
- **Simultaneous updates (Problem 2).** Marking counties as soon as they are found would let a county infected today help infect its neighbor on the same day. On input 1, that version jumps straight to the Day 3 board on Day 2. Collecting the whole day's list before marking anything fixes this, and the Day 1–4 boards of input 1 match the assignment's example exactly.
- **Checking only where something changed (Problem 2).** Scanning the whole grid every day repeats a lot of work. Checking only the neighbors of yesterday's new infections makes the total work proportional to the number of counties, O(N²), however many days the spread takes.
- **One pass with sets, and a formula for sub-boards (Problem 3).** Checking rows, columns and sub-boards in separate passes would also work, but a single pass with three lists of sets does all three at once. The formula `(r // k) * k + c // k` gives each cell's sub-board without any extra loops.
- **Every program runs the same way in every shell.** All three programs accept the input file name as an argument, which works in PowerShell too, where `<` does not. Standard input still works, and a byte-order mark added by a PowerShell pipe is removed before parsing.
- **Tested against brute force.** Besides the sample inputs, each program was compared with a simple brute-force version on random inputs, and all results matched:
  - **Snowfall:** 3,000 arrays, including exact-half windows, n < 3 and decimal amounts.
  - **Pandemic:** 1,500 grids, compared with a full-grid daily scan on both the final grid and the number of days.
  - **Puzzle:** 3,000 1×1, 4×4 and 9×9 boards, including unlisted symbols, compared with counting every row, column and sub-board.
